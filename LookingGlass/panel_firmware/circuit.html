LookingGlass Control Panel — Circuit / System

Board: ESP32-S3-ETH (ESP32-S3R8 · 16 MB flash · 8 MB PSRAM · W5500 Ethernet + PoE) — same board as BM26-Stoker. 6 illuminated buttons, active-low to GND, each = 2 IO (switch + PWM LED): SW1–SW4 small arcade, SW5 big arcade, plus a green Mode button with a status LED. Switch pins mirror Stoker's control-panel map.

Notes

  • Active-low, internal pull-ups. Each button connects its GPIO straight to GND; firmware sets INPUT_PULLUP, so no external resistors are needed. Pressed = LOW.
  • Debounce. Firmware debounces in software (DEBOUNCE_MS = 15). An optional 100 nF cap across each switch (pin→GND) adds hardware filtering but is not required.
  • Power. The board is fed from USB-C 5 V (VBUS) — same port used for flashing/serial. Share a common GND with the board, all switches, and the LED rail.
  • Button LEDs (×6). Every button — the 4 small arcade, the 1 big arcade, and the Mode button — is illuminated. Each LED is on its own PWM GPIO (SW1–SW5.PWM.LED = GPIO 41/1/2/42/21, Mode = GPIO 47). Two wiring options (toggle the sub-tabs above the buttons plot): (A) Direct drive — no MOSFET yet: GPIO → 330 Ω → LED → GND, PWM-dimmable but only for low-current LEDs (≤ ~20 mA @ 3.3 V). (B) Low-side N-MOSFET: gate via 150 Ω (+ 100 kΩ pulldown), LED on a separate 5 V/12 V rail — required to fully light the 5/12 V arcade-button lamps. Future work: one ULN2803A 8-channel board replaces all the discrete drivers — amazon.com/…/B08C5B1S47 (GPIO→IN, LED+→rail, LED−→OUT, COM→+rail, GND→common; no gate R/pulldown needed).
  • Stoker-compatible IO. The switch pins mirror BM26-Stoker's control-panel map so harnesses/firmware knowledge transfers: SW1–SW5 = 15/18/16/39/40 (Stoker P1-A/P2-A/P3-A/P1-B/P2-B), Mode = 17 (Stoker MODE), Mode LED = 47 (Stoker mirror-LED). Polarity differs: LookingGlass buttons are active-LOW (INPUT_PULLUP, →GND); Stoker FIRE buttons are active-HIGH (INPUT_PULLDOWN, →3V3) for fire safety — these don't actuate fire, so active-low is fine.
  • Network. The panel reaches the LookingGlass unmanaged switch over wired Ethernet via an onboard W5500 (ESP32-S3-ETH) and an RJ45. See the System Overview tab for the whole two-side network.
  • Status LED is the module's onboard WS2812 on GPIO48 (the ETH board's RGB pin) — already wired on the board.
  • Reserved pins — never assign a button here: 33–37 (octal PSRAM), 38 & 48 (RGB-LED), 19/20 (native USB), 43/44 (UART0), 0/3/45/46 (strapping), 9–14 (W5500 SPI), 26–32 (flash). After this map nearly every header GPIO is used or reserved.

Data flow

  • Two-side system. The Titanic ship side runs the main MarsinEngine on the Server; the LookingGlass podium side runs a small MarsinEngine on the Raspberry Pi, a Chroma.tech Angio LED controller, and the ESP32 panel controller.
  • LookingGlass LAN. The Pi, the Angio, and the ESP32 panel all connect to a single unmanaged switch over Ethernet.
  • Cross-site link. The unmanaged switch joins a point-to-point long-range network to the server-side switch, linking both LANs.
  • Podium lighting. The Pi controls the podium LEDs by streaming sACN (E1.31) to the Angio over Ethernet; the Angio drives the LEDs.
  • Panel → ship. The ESP32 panel sends button data to the Pi's bridge, which translates it and forwards it to the Titanic ship over the long-range network.
  • Panel → podium. The panel also drives the Pi, which emits sACN to the Angio over Ethernet — so the buttons light the podium directly.
