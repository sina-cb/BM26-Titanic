## Headline: the knob-value bug is ALREADY FIXED on this branch

Sina's report ("mode works; the knob value 0-127 is NOT being properly set")
was the **pre-branch** state. Root cause, now confirmed from both the host diff
and the device report:

- **Device side (old):** the VSN1 endless encoder's event fn is `epc`, so
  factory auto-MIDI sent the **relative 63/65 stream on CC 40** — the host never
  saw an absolute value. (`encoder_turn.lua` header; report `20260708_6`.)
- **Host side (old):** the jog CC match was **pinned to channel 0** (the single
  capture was taken on page 0). Auto-MIDI transmits on **channel = current page**
  (`(module_y*4 + page) % 16`, report `20260708_6` line 292-296), so every jog
  turn on pages 1-3 was silently dropped. (`profile.ts` diff documents this
  verbatim as the "knob does nothing" bug.)

**The fix on this branch (the "keyed value contract", firmware redeploy
2026-07-11) — verified correct end-to-end:**

1. **Device** `templates/effects_layout/encoder_turn.lua` emits an explicit
   absolute per-slot CC: `midi_send(-1, 176, 32+sel, vals[si])` = channel `-1`
   (auto → **page**), command `176` (CC), controller `32+sel`, value `0..127`.
   Asserted by `test_offline.cjs:222` (`gms(-1,176,32+sel,vals[si])`).
2. **Host** `profile.ts` binds it with `anyChannel:true` + `ccTo:39`;
   `resolver.ts` computes `slotId = 8*channel + (cc-32) + 1`, `value = v/127`,
   producing a concrete `effectIntensitySlot`.
3. **Host** `manager.onMessage` coalesces it **per slot**
   (`${controlId}#s${slotId}`) so two keys turned in one window can't clobber
   each other, then `flushResolved` → `dispatch` `effectIntensitySlot` →
   `api.setGlobalEffectSlotIntensity` → `POST /global-effect-slots/:id/intensity`.
4. **Engine** `setSlotIntensity` maps `v01` onto the effect's real primary range
   (`min + (max-min)*t`), writes `paramsOverride[param]`, applies live if running.

## Hardware test script for Sina (what to see at each step)

Prereq: VSN1 on COM12, engine `:6968` + CaptainPad `:6967` up (they are).

1. **Knob value (page 0).** Press a slot key with a value (e.g. "Punch" /
   "Ghost Trails"), turn the encoder. → LCD value bar + 5-LED ring track the
   turn; the effect's intensity changes live on the rig; CaptainPad's slot
   value updates. **This is the bug that's now fixed — confirm it moves.**
2. **Knob value on pages 1-3.** Assign an effect to a page-1 slot first (UI),
   press sb_1 (page 1), select that slot, turn. → value applies to the page-1
   slot, NOT a page-0 slot. (Before the fix this did nothing.)
3. **Two-step toggle.** Press an un-selected toggle key → LCD shows it, key
   does NOT light (select only). Press the SAME key again → effect turns ON,
   key lights. Press a THIRD time → effect turns **OFF**, key unlights.
   (Sina's "toggles on and never off" — confirm it now goes off.)
4. **Trigger slot.** Press a trigger key (e.g. "Iceberg Flash") → fires on
   EVERY press, no two-step.
5. **Mode cycle.** Select a slot with a mode (e.g. "Punch" Source), press the
   encoder → LCD mode label advances one step each press, wraps at the end.
6. **Page switch.** Press sb_0..sb_3 → LCD page index changes, the 8 keys
   repaint for that page's slots, side-button LEDs follow. CaptainPad's page
   switcher converges to the same page.
7. **Downward feedback.** Change a slot's value/mode/active from the CaptainPad
   UI → the VSN1's key LED / ring / LCD update to match (engine is the single
   source of truth; every surface mirrors it).
