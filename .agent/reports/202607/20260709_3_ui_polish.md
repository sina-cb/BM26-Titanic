## Why the effects panel first

The 4-page × 8-slot grid, page switcher, P-badge, and the slot value/mode
sheet all landed in Effects v2 with utilitarian styling. It is also the one
surface mirrored on physical controllers (APC scene column, VSN1), so its
states have to read instantly at arm's length in the dark.

## Changes + rationale

### 1. Theme-correct "on" text (real contrast bug, all bright-primary themes)
- Every `'#FFF'`-on-`primary` pairing → `C.onPrimary`: active page segment,
  ON slot chips, chip badges, ⋯ glyph, detail-sheet step/mode chips.
  The dark/midnight/sunset/gruvbox themes use BRIGHT primaries (cyan, amber,
  mustard) where white text washed out — verified visually: "P1" was
  near-invisible white-on-cyan in dark mode. `onPrimary` is each palette's
  guaranteed-contrast pairing and is what the rest of the app already uses.
- BLACKOUT ON label → `C.background` (not `#FFF`): dark themes soften
  `error` to light salmon where white also failed; `background` is each
  theme's opposite pole, so light keeps white-on-deep-red and dark gets
  near-black-on-salmon.

### 2. Page switcher → one segmented control
Four loose ghost-bordered slabs became joined segments inside a recessed
`surfaceDim` track (the same recessed language the empty slot sockets use):
"where you can go" reads distinctly from "what you can fire". Active
segment = solid primary fill. Added a small `tertiary`-green **activity
dot** on any page that has a live effect — derived from the status array the
chips already consume (no fetch, no state, no interaction change), so a
running effect on another page stays glanceable.

### 3. Slot chips — two-band layout
- Top band = meta: value/mode badge (top-left, 9px in a 16px pill, was 8px
  in 14px) and the ⋯ edit affordance (18px, moved back to top-RIGHT).
  Label owns the band below (`paddingTop: 14`, uniform on every chip so
  labels share one baseline across the strip). This resolves the collision
  chain: bigger badge overlapped centred labels; lowered labels then hit
  the old bottom-right ⋯. One reserved meta band fixes both by
  construction. (QA round7 had moved ⋯ to the bottom corner because labels
  were vertically centred then — that constraint no longer exists.)
- Strip chips 44→48px tall (landscape) to pay for the meta band; label
  12px (was 11) for arm's-length legibility — chips are ~150px wide in the
  landscape bar, so the room was already there.
- Radius 6→8 everywhere in the panel (chips, empties, skeleton, blackout,
  switcher) — the app's control chips sit at 8+; the panel was the only
  6px-radius surface. Gap unified to 6.
- Removed GEM's inner top border in strip mode — the host bottom bar
  already draws one; the doubled hairline mid-bar is gone.

### 4. Slot detail sheet (value/mode editor)
Now matches the app's card language: 16px radius, ghost border (essential
in dark themes where the sheet fill nearly matched the scrim), soft ambient
shadow, 20px padding. Title row = small "SLOT n" pill + effect name at 15px
(was one cramped uppercase line). Each section is a label row with the LIVE
value right-aligned in `primary` ("PUNCH STRENGTH … 100%"), then its
control row; hairline divider between sections. Step buttons 32→40px and
mode chips to 40px (comfortable touch targets); CLOSE is a proper 46px
bordered bar. No interaction added or removed.

### 5. Swap sheet
Same card treatment + same title-row family as the detail sheet. Preset
rows are one-line (min 44px): label left, behavior ("toggle"/"trigger") as
a small right-aligned tag instead of a sub-line — faster to scan in a long
library. REMOVE sits on `errorContainer` fill so destructive reads at a
glance. Group headers unified with the app's section-label style.

### 6. Small unifications
Header title 10px both variants (9px strip size was below the app's
smallest caption step); PAGE badge 15→18px pill; error text 10→11px;
letter-spacing on hard-action labels (BLACKOUT, CYCLE, RESET) at 0.8.
