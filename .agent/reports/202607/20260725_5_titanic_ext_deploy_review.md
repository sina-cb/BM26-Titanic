## 4. Smoothness delta — RESOLVED by operator (not hardware, not version)

The operator diagnosed it mid-investigation: **music sync was on and drove
the GLOBAL SPEED parameter to a very low value**, which read as lag/choppiness
("I think" — tentative, operator-diagnosed). The deep perf root-cause hunt and
profile benchmarking were descoped on that basis.

**Pointer for a candidate follow-up** (noted in passing, not investigated):
the tempo→speed mapping lives in `marsin_engine/lib/bpm_speed_sync.js`
(`recompute()`, ~lines 170–191):
`speed = clamp01((bpm − bpmSpeedMin) / (bpmSpeedMax − bpmSpeedMin))`, then
multiplied by a `_speedScale` layer (the audio_reactive autopilot can "sag"
it), re-clamped to [0,1], and written to CPC `speed`. **There is no floor**:
a BPM at/below `bpmSpeedMin` (or a sagged scale) writes `speed` down to 0.0.
Follow-up question for the operator/board: should bpm-speed-sync have a
configurable floor (e.g. never below 0.1) so a low/wrong tempo can't visually
freeze a pattern? Related: on titanic-ext the companion's mic is dead (§2),
so whatever tempo the sync saw there was not live room audio.

## 5. Recommendations (lower priority — original motivation resolved)

Brief options if we ever want the show servers cheaper/faster, ranked:

1. **Run show servers headless (drop `open_browser`)** — the physical LED
   path for engine-owned universes goes engine → sACN → controllers directly
   (`marsin_engine/config.yaml` `controllers:`); the browser sim is a monitor
   for those. Caveat before flipping it: fixtures routed through the
   *browser's* DMX pipeline (browser → WS → `simulation/server/sacn_output_bridge.js`
   → sACN) DO need a browser page; verify per-scene routes before going fully
   headless on a machine that owns DMX fixtures.
2. **Weak-GPU sim profile via deploy overlay** — the sim already ships a
   purpose-built `2d_pixels` profile (`simulation/src/core/profile_registry.js`,
   `headless: true`; `animate.js` skips ALL per-frame 3D GPU work but keeps the
   DMX/sACN pipeline + 2D pixel map). Sanity probe on the laptop: `2d_pixels`
   held 60 fps even under a pure-CPU rasterizer, while 3D profiles collapsed
   (full ≈ 1 fps) — so it is the right choice for any box with no/weak GPU.
   Wire it per-machine via `deploy/overlays/<machine>/` or a supervisor URL
   tweak (today `boot_server.ps1` hardcodes `profile=edit` in `$simOpenUrl`).
3. **Hardware** — titanic-ext's Vega 7 iGPU is hardware-accelerated and fine
   for `edit`/monitoring duty; no evidence it needs replacing for prod duty.
   If richer on-box 3D preview is ever wanted there: set power plan to High
   performance, prefer 1080p over 1440p for the sim window, or add a dGPU.
