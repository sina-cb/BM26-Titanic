## 1. Why the plan's §1.2 doc paragraph could not be applied verbatim

`_363` §1.2 told S4 to strip gamma from both docs entirely — remove the
`GET /led/gamma` **and** `POST /led/gamma-push` proxy sections, and annotate
`gamma` as "not consumed or written by this repository". After `_364`'s rulings
that is **false in two places**: the gamma-push route, service and CLI are alive
(dormant), and the gamma UI still renders (disabled). The docs were therefore
written to the **post-S1/S2 truth**, not to the plan's §1 end state:

| Plan §1.2 said | What the docs now say (and why) |
|---|---|
| remove the `POST /led/gamma-push` section | section **kept**, rewritten as **dormant** — the route works, is tested, and nothing in the UI calls it (`_364` §2) |
| remove the `GET /led/gamma` section | **removed**, and the doc states the read route is gone permanently, "only push, not pull" |
| "gamma: not consumed or written by this repository" | "never **read** by the repository; written only by the dormant push route the disabled UI never calls" |
| gamma is manual "and the preview models a fixed linear response" | gamma is manual; the preview models a fixed **linear** response **unless the scene YAML declares otherwise** — `controllerGamma` preview values were KEPT (`_364` §6), so the blanket claim would have been wrong |

S3's surface (pre-write identity gate, narrowed warning copy, DMX ⏻ toggle,
sync-chip swarm clause removed) is documented as the **current design** per the
brief. At the time of writing, `led_discovery_panel.js` had not yet landed those
edits — see §5, deviation 1.

## 5. Deviations and truthfulness notes

1. **S3 is documented as the current design while its code was still in
   flight.** Per the brief (§C), the pre-write identity gate, the narrowed
   warning copy, the DMX ⏻ toggle and the removed sync-chip swarm clause are
   described in both docs as how the system works. A grep of
   `simulation/src/gui/led_discovery_panel.js` at the time of writing found no
   `toggleDmx` / `buildDmxToggleBody` reference and the old swarm-era
   `FORCE_PUSH_WARNING` copy still in place — i.e. **the docs currently lead the
   panel code by one slice**. They become true when S3 lands; if S3's shape
   changes, §4.1/§4.4/§4.5 of docs/41 and the toggle + write-sequence sections of
   MARSINLED_API.md are the places to re-check. The client-side halves the docs
   describe (`buildDmxToggleBody`, `diffDmxToggle`, `pushDmxToggle`,
   `swarmEnabledNote`, the narrowed body and verify) **are** landed and were
   verified present in `marsinled_client.js`.
2. **The swarm informational note is documented as a note on the outcome line,
   not as part of the verify verdict** — matching `_365` deviation 1
   (`swarmEnabledNote` is a separate pure export; putting it in the mismatch
   array would turn an intended state into a failure). Both docs state it is
   informational and non-failing, and neither claims `diffForcedConfig` returns it.
3. **`dmx.universe` / `dmx.startAddress` are documented as PRESERVED**, per
   `_365` deviation 2 and §2.1's merge rule — a real change from the `_362`
   behaviour that dropped them. docs/41 §4.1(b) states it explicitly and adds why
   it is harmless (they are inert while per-output universes are in force) so a
   future reader does not "fix" it back.
4. **`_363` §1.2's own doc instructions were partly superseded** — see §1 above.
   The four-row table there is the audit trail for every place this slice
   deliberately did not do what the plan said.
5. **`_363` §1 and §11 are still stale** and were not edited by this slice (the
   brief scoped S4 to exactly two files). `_364` §7 already records that they
   must be marked superseded; docs/41 §7's new gamma item now carries the
   still-live part of §11 (push-only return, no pull) so the doc tree does not
   depend on that correction happening.
