# _182 — Global SIZE locked at 0.5

Date: 2026-08-06 · Agent: _182 (Opus implementation) · Branch: feat/bm_readiness

## Operator ruling

> "Set it to 0.5 and do not allow changing it. Add some warning in the engine
> UI if it's anything but 0.5."

Context: _181 (`.agent/reports/202608/20260806_181_coordinate_range_story.md`)
traced the titanic calibration planes topping out at ~0.47 to a persisted
`size: 0.773` in the scene globals. The engine-owned SIZE fader rescales every
pattern coordinate once per frame (`wasm_host.applySizeScale`, driven by
`engine.js` `globalSizeMultiplier()` = `0.25 · 16^size`, identity at 0.5), and
no UI has carried a SIZE control since 2026-07-27 — so a stray persisted value
was unfixable by the operator and silently corrupted their readings.

## 1 — The live engine (done first, operator-authorized)

The running titanic engine was fixed through its own API — a client call,
exactly what a UI fader would do. No restart, no port bound, no hand-edit of
`marsin_engine/states/**`.

| Step | Result |
|---|---|
| `GET /param-center` (before) | `size: { value: 0.773, lastSource: init, lastRevision: 2 }` |
| `POST /param-center {"size":0.5}` | `{ status: ok, revision: 195470315 }` |
| `GET /param-center` (after) | `size: { value: 0.5, lastSource: api, lastOrigin: api }` |
| `states/titanic/globals_state.yaml` | rewritten **by the engine itself** to `size: value 0.5` |

Coordinates on the live rig now span the full 0 → 1 again (multiplier 1.0×).

## 2 — The pin (takes effect at the operator's next engine restart)

One constant, one module, deliberately no config option and no env override.

**`marsin_engine/lib/size_lock.js` (new)** — `LOCKED_SIZE = 0.5`,
`SIZE_LOCK_KEY`, `SIZE_LOCK_REASON`, `SIZE_LOCK_MESSAGE`, `isLockedSize()`, and
`SizeLockReport` (per-ParamCenter record of everything that fought the lock).
The file header carries the ruling, the why, the report references, and the
one-paragraph "to unlock" instruction.

**`marsin_engine/lib/param_center.js`**

- Registry entry `size` now takes `default: LOCKED_SIZE`, label `Size (LOCKED)`,
  `locked: true`.
- `_loadFromDisk()` — the persisted value is **never** restored: a non-locked
  value logs loudly (naming the file and the ignored value) and the store keeps
  the pin.
- `_setNoFire()` — the SIZE guard sits **before** source arbitration, so every
  writer lands on it. Returns
  `{ status:'ignored', reason:'size_locked', lockedValue:0.5, noop, message }`
  and never throws. A write that asks for 0.5 sets `noop:true` and is **not**
  counted as a violation (a clean state file must not warn every boot).
- `getAll()` / `getCanonicalState()` / `_writeToDisk()` serve the pin through
  `_pinnedSize()`, which loudly reports and repairs any hypothetical store
  drift — so the render loop, WS broadcasts, and persistence are pinned at the
  READ side too, not just the write side.
- New public surface: `getSizeLockReport()`, `getSizeLockWarning()`,
  `noteSizeLockRestoreFile(file, value)`.
- `getSchema()` gains `locked` / `lockedValue` so any UI can render it
  read-only.

**`marsin_engine/lib/state_manager.js`** — `applyGlobalsState()` detects the
refusal and calls `noteSizeLockRestoreFile()` with the actual path, so the
operator is told **which file** carried the stale value. Optional
`restoreLabel` arg added for snapshot/look recalls (defaults to the scene's
`globals_state.yaml`).

**`marsin_engine/lib/api_server.js`**

- `POST /param-center` — every other key in the body still applies; a refused
  size write then returns **409** via the existing `sendJsonError` idiom with
  `{ error, reason:'size_locked', key, requested, lockedValue, revision }`.
- WS `setSharedParam` — the existing `paramRejected` frame now also carries
  `message` and `lockedValue` so a client shows *why*, not just a code.
- Timeline `setParams` dep — a hand-authored cue/look still carrying `size`
  throws with the full lock message (surfaces as a cueError, the established
  "authoring error fails loud" idiom); a cue asking for 0.5 is skipped as a
  no-op.
- `GET /status` — new `sizeLockWarning` (string or null) and `sizeLock` (full
  record).

### Every set path, and how it is covered

All CPC writes funnel through `set` / `setHsvField` / `setMany` → `_setNoFire`.
Verified by enumerating every `paramCenter.set*` call site in the engine:

| Path | Call site | Covered by |
|---|---|---|
| REST `POST /param-center` | `api_server.js` | guard + 409 response |
| WS `setSharedParam` | `api_server.js` | guard + `paramRejected` frame |
| OSC packets | `osc_listener.js` → `setMany` | guard (size dropped from batch) |
| Timeline cue / look globals | `api_server.js` `deps.setParams` | guard + cueError |
| Colour autopilot | `api_server.js` `writeColorPaletteParams` | guard (never writes size in practice) |
| Boot state restore | `state_manager.applyGlobalsState` → `set(..,'init')` | guard + file-named warning |
| Snapshot / look recall (perf-mode exit) | same function | same |
| CPC's own `param_center_state.yaml` | `_loadFromDisk` | pin + file-named warning |
| Audio companion / detector / derived signals | `setMany` | guard (audio keys only) |
| Pattern variable injection | `registerChannel` | `engineOwned` already skips binding `size`; pinned by test |

Non-writers confirmed by inspection: `playlist_manager`, `snapshot_manager`,
`modulation_controller`, `channel_param_router`, `bpm_speed_sync`,
`tempo_arbiter`, `mood_source` (read/subscribe only). `applySizeScale` has
exactly one caller (`engine.js:791`) and it reads the pinned `getAll().size`.

## 3 — Where the operator sees the warning

The engine serves **no** web UI of its own (`marsin_engine/` has no
web/public/ui directory; `tools/midi_discovery` and `tools/param_truth` are
offline tools). The operator's UI is CaptainPad, so the warning rides the
status payload CaptainPad already polls:

- **Engine** — `GET /status` → `sizeLockWarning`, a ready-to-render one-liner,
  e.g. `SIZE locked at 0.5 — saved state carried size=0.773
  (…/titanic/globals_state.yaml); 1 write(s) refused, last 0.773 from init`.
  `null` when clean. `sizeLock` carries the full record (which file, how many
  refusals, per-source counts, last refusal).
- **CaptainPad** — the existing amber **⚠ DEGRADED** header chip
  (`components/ui/HealthChip.tsx`) on the Deck and Mixer screens. `utils/api.ts`
  types the field, `hooks/useEngineState.ts` seeds it into `engineHealth` on
  every `/status` probe, and `deriveEngineHealth()` checks it **first** (ahead
  of the blend / deck-restore degrades) because it is the only one the operator
  cannot diagnose from the UI. Tapping the chip shows the full line. A clean
  engine reports `null` → chip renders nothing, no layout shift.
- **Console** — a loud `⛔ [size-lock]` line on every boot override and every
  refused write. Refusal logs are aggregated after the first one (at most one
  line per 2 s, with the suppressed count folded into the next line) so a stuck
  30 Hz writer cannot flood the console mid-show. Nothing is dropped: the count
  is exact and always visible on `/status`.

The warning is **sticky** for the process lifetime — it never self-clears, so a
refusal that happened hours ago is still visible.

## To unlock (a future ruling)

Delete the `SIZE_LOCK_KEY` guards in `param_center.js` (`_setNoFire`,
`_loadFromDisk`, `_pinnedSize`) and `marsin_engine/lib/size_lock.js`. The
`/status` fields and the CaptainPad chip branch degrade to permanently null.
There is no runtime switch by design — codex P0 forbids a fallback path around
a hard rule.
