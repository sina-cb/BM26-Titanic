# _180 — Par halo leak debug (sim-only glow on OFF pars)

**Agent:** _180 (Fable debug) · **Date:** 2026-08-06 · **Branch:** `feat/bm_readiness`
**Bug (operator):** live titanic scene, sACN-in — a par that should be OFF is dark on
hardware and its three.js SpotLight is off, but a halo glow still renders around the
fixture in the sim. Intermittent.

## Verdict

One provable defect chain found and **fixed** (small, offline-pinned). Two weaker
hypotheses remain live-discriminable; recipe below. No sim/engine/bridge processes were
touched (operator's stack in use).

## How a par halo gets its color (verified mechanics)

Pars are `DmxFixtureRuntime` (UkingPar). The halo is an instanced additive
BackSide rim (`simulation/src/fixtures/led_halo.js` recipe); its color rides in
`haloInst.instanceColor`, written ONLY by `_writePixelColor`
(`simulation/src/fixtures/dmx_fixture_runtime.js:592-610`), which also writes the bulb,
the cone and `p.color`. Black color ⇒ invisible halo (additive). Per frame in sACN-in
(`simulation/src/core/animate.js:484-561`):

1. `dmxRouter.processFrame()` — engine bytes → universe buffers.
2. `demapSacnToPixels` (:504) — paints entries + fixture via `entry.apply` (no dimmer,
   W/A/U-blended); undriven entries get `paintUndrivenEntry` (black/red).
3. `applyFixtureOutputOverrides` (:527) — sim overrides zero the buffer.
4. `applyDmx → fixture.applyDmxFrame` (:530-553) — LAST halo writer: dimmer-honest,
   RGB-only, straight from the buffer. Runs only if the fixture has a live
   universe/addr AND `getFullFrame(universe)` is non-null.

So a par with a live frame is self-correcting every frame: engine zeros ⇒ black halo.
A leak requires a fixture that step 4 **cannot reach** (unpatched par, or par patched
to a universe this browser holds no frame for) **plus** an out-of-band paint that the
undriven repaint never clears.

## Root cause (fixed): out-of-band config-color paint + undriven fast path

Three parts, each individually correct:

1. **`paintUndrivenEntry` fast path** (`simulation/src/dmx/sacn_mapper.js:198-209`):
   once an entry is marked `_sacnUndriven` and its r/g/b/w/a/u fields match the
   treatment, it returns WITHOUT calling `entry.apply()`. Pinned perf contract
   (`tests/sacn_mapper.test.js` "apply fires once, not per frame"). Sound only while
   nothing repaints the fixture behind the entry's back.
2. **`⚡ Enable` OFF handler** (`simulation/src/gui/gui_builder.js:1735-1755` pre-fix):
   paints EVERY par its config color (default `#ffaa44` amber) at **full brightness,
   ignoring outputGain**, directly via `setPixelColorRGB` — bulb + halo + cone +
   `p.color` — with **no batch-cache invalidation**. Meanwhile the lighting-disabled
   clear loop (`animate.js:464-482`) writes the entry fields to exactly the black
   treatment values.
3. **Re-enable lighting**: for every still-marked undriven entry the fast path sees
   marker + matching fields ⇒ skips forever. The fixture keeps the amber paint: lit
   halo on an off par. The SpotLight pool reads `p.color` but gates independently
   (budget/frustum/`outputGain() <= 0` at `light_pool.js:462`), so "halo without
   spotlight" is exactly what renders. Matches sim-only + intermittent
   (state-dependent on the Enable toggle + undriven-marked entries).

Related aggravator (recovers on its own, explains brief flashes): the
`DmxFixtureRuntime` constructor seeds all pixels to config color (:450-451), and
chunked par rebuilds export a batch list without par entries until `_finishRebuild`
invalidates — a sub-second amber window during any fixture rebuild in sACN-in.

### Fix applied

`simulation/src/gui/gui_builder.js` — the Enable-OFF reset now calls
`window.invalidateMarsinBatchCache('lighting_disabled_reset')` after its out-of-band
paint. The rebuild clones fresh entries (the private `_sacnUndriven` marker is not part
of the exporter pixel shape), so the next demap pass repaints every undriven fixture
with the real treatment. One call + comment; no behavior change for driven fixtures.

### Pinning test (offline)

`simulation/tests/par_halo_undriven_repaint.test.js`:
- behavioral: marked-undriven entry with matching fields is NOT repainted (the fast
  path is real — the leak's precondition);
- behavioral: a fresh clone (what invalidation produces) IS repainted black;
- source contract (repo's established pattern, cf. `unpatched_red_two_views.test.js`):
  the Enable-OFF reset block must contain the invalidation call.

**Results:** new file 3/3 pass; adjacent suites (`sacn_mapper`, `halo_driven_color`,
`dmx_halo_visibility`) 32/32 pass. Full sim suite: 2148/2156 pass — the 7 failures are
pre-existing live-stack/scene residue (e.g. `scenes/summer_camp_dome/patches.yaml.original`,
dated Jul 5; live-modified `scenes/**`) in scene-content tests that do not import any

## Remaining hypotheses (if the leak recurs after this fix)

Ranked; all sim-side, all discriminable live in <5 min:

- **H2 — frozen universe buffer.** `UniverseRouter.processFrame`
  (`simulation/src/dmx/universe_router.js:116-162`) holds the LAST received frame
  forever once a universe stops arriving (per-SOURCE staleness only — one shared
  `SACN_SOURCE_ID` for all universes, `sacn_input_source.js:428`, stays "active" as
  long as ANY universe flows; a stale universe's buffer is never blacked). If the
  bridge stops forwarding one universe (bench-mirror arm/route churn on this very
  branch), that par freezes at its last LIT color. Would normally light bulb+dots+
  spotlight too — but a pool-budget/distance miss can present as "halo only".
- **H3 — demap vs applyDmxFrame lane asymmetry.** Demap blends W/A/U with no dimmer
  (`sacn_mapper.js:120-174`, par channel map `{r:2,g:3,b:4,w:5,a:6,u:7}` — dimmer ch1
  deliberately absent); `applyDmxFrame` uses dimmer × RGB only and ignores
  white/amber/purple (`dmx_fixture_runtime.js:838-868`). Self-correcting while step 4
  runs (last writer), but the scene-wide instanced DOT reads the demap lanes — a
  UV-only engine residue (u=ch7) renders a purple glow dot at the fixture while
  hardware UV reads near-dark to the eye. "Glow at the fixture, no spotlight."

### Discrimination recipe (operator or Opus agent, AFTER the stack is free)

1. Reproduce, then in the browser console on a leaking par (index `i`):
   `f = window.parFixtures[i]; f.pixels[0].color` → amber `{~1, ~0.67, ~0.27}` ⇒ the
   fixed W3 chain (confirm fix works: toggle ⚡ Enable off/on — leak must now clear
   next frame). Any other lit color ⇒ H2/H3.
2. `u = f.patchDef?.universe; window.dmxRouter.getFullFrame(u)` — `null` ⇒ step-4
   unreachable (H1/H2 territory); non-null: dump bytes at `addr-1 .. addr+9`.
   All zeros with a lit halo ⇒ NEW writer (report back); nonzero ⇒ compare with what
   the engine believes it sends (`GET 127.0.0.1:6968/status`) — mismatch ⇒ H2 frozen
   buffer; match with only ch7 (purple/UV) nonzero ⇒ H3.
3. Visual confirmation via the operator or `.agent/skills/see_the_world.md` renders —
   only after the operator frees the stack.

### Fix sketches if H2/H3 confirm

- H2: track per-(source, universe) `lastSeen` in `universe_router.js`; when a universe's
  last frame is older than `SOURCE_STALE_MS`, write a zero frame once (loud log, no
  silent fallback semantics — the frame is the only truth and an absent frame is dark).
- H3: read `dimmer` (and white/amber/purple with the same additive weights the demap
  uses) in `applyDmxFrame`, and carry the dimmer channel in the exporter's
  `standardizeChannels` so the demap can honor it — one shared par lane map, two
  consumers.
