### N1 (F4) — fail-loud consistency in `mixer.tsx`

The fader/mute/solo/view-selection handlers already surfaced `{ok:false}`. I
verified and fixed the remaining call sites that ignored the now-meaningful
result:

- **name** (`onEndEditing`, ~ln 264): capture `res`, `console.error` on
  `!res.ok`. Cosmetic field — log only, no Alert, no revert (uncontrolled
  `TextInput` keeps the typed text; next mixer broadcast re-syncs).
- **blend MODE** (`handleModeChange`): operator-critical → revert local mode
  (state + `savedModesRef`) to the captured prior mode AND Alert, matching the
  view-selection handler.
- **playlist lock engage** (`handleLockToggle` locked branch): operator-critical
  → revert + Alert.
- **playlist lock release** (`handleLockToggle` clean-unlock branch): revert +
  Alert.
- **lock release after unlock-dirty resolve** (`resolveUnlockPrompt`):
  save/discard already committed, but the lock release itself can be rejected →
  revert lock, keep the prompt open (pending:false), Alert.
- **fader-lock** (`handleFaderLockToggle`): less critical (gates drags, not
  saves) → revert the optimistic flip + log, no Alert spam.
- **transition settings** (`handleTransitionSettingsChange`): mode/time live in
  the child `ChannelStrip`'s local state (re-synced from engine on next mixer
  broadcast), so the parent cannot cleanly revert → log on `!res.ok`, no Alert
  (these tune HOW a transition runs, not the live mix).

No per-broadcast alert spam was added; alerts are limited to operator-critical
MODE/lock paths, consistent with the existing view-selection handler.

### N2 (F2) — typed WS rejections

Verified the engine payloads in `marsin_engine/lib/api_server.js`:
- `channelFaderRejected` → `{type, channelId, fader, reason}` (ln 4761).
- `channelModeRejected` → `{type, channelId, mode, reason}` (ln 4798).

The engine returns from those handlers WITHOUT broadcasting a fresh `mixer`
state, so a rejected optimistic write would silently stick. Added an
`else if (msg.type === 'channelFaderRejected' || msg.type === 'channelModeRejected')`
branch in the `onControl` handler that: clears the `localFaderWriteRef` hold for
the channel (so the re-sync isn't suppressed by the fader drag guard), emits a
throttled (1/sec/channel via the existing `throttleRef`) `console.error`, then
re-fetches authoritative state via `fetchMixerState()` and overwrites ONLY the
rejected channel's value. `EngineMessage` is an open `{type; [k]: unknown}` type,
so no type-decl change was needed.

### N5 (F7) — hot-swap re-entrancy

`PlaylistPanel.tsx` `handleHotSwap` guarded only on `swapInFlight` STATE; two
confirms in the same tick could both read `false` before the first
`setSwapInFlight(true)` flushed. Added a synchronous `swapInFlightRef` that flips
before the state set and clears in `finally`. State is retained for the
disabled/opacity chrome. Dropped `swapInFlight` from the `useCallback` deps (no
longer read inside) — verified no new lint warning.
