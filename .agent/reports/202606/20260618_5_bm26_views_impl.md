The only golden change is `titanic/27_swipe`, and it is a **fix**: the pattern
was rendering the whole rig black on titanic (the report-1 bug) and now lights
its fixtures via model-independent `FIX_*` targeting. Its mean jumped
0.09→1.39 ms — that is the *real* cost of a pattern that actually paints pixels
(the old 0.09 ms was an artefact of early-returning black on every pixel). p99
1.59 ms is comfortably under the 5 ms hard ceiling. Every other pair is
byte-identical (golden-hash stable), proving the fixture-type and named-mask
machinery is additive and zero-impact on patterns that don't use it.

Gauge note: because every matrix pair runs sub-millisecond (~100–1300× under
the 25 ms budget), the relative p99/mean/compile gates engage only above a
noise floor (1.0 ms frame / 3.0 ms compile) — below it a 5–8 % delta is pure
scheduler jitter, exactly as `_4` §4.4 anticipated ("the absolute 5 ms ceiling
is the real backstop"). The exact (non-timed) bytecode-size proxy and the exact
golden-hash oracle catch correctness/output regressions independent of timing
noise. `titanic/27_swipe` (p99 1.59 ms) now sits above the floor and IS guarded
by the relative p99 gate.

## INTEGRATION TODO — Tier-B host-side changes (the next step must make these)

Tier B exposes a true per-pixel `fixtureType` integer builtin + a
`pixelLocalIndex` builtin from the rebuilt MarsinLED WASM, replacing the
Tier-A viewMask-bit encoding. The BM26 side is already aligned: the canonical
`FIX_*` id table is owned here and is **append-only**. The integration step
must add the two new Int32 lanes to the per-pixel meta pack. **Do NOT change
this packing until the rebuilt WASM that reads a 6-int stride is vendored** —
the stride is an ABI contract; JS and WASM must change together.

### 1. `marsin_engine/lib/wasm_host.js` — `setPixelMeta` (current lines)

- **`:250`** `const metaBufSize = this.pixelCount * 4 * 4;` → grow `4` to **`6`**
  (six Int32 per pixel).
- **`:251–252`** the `Int32Array` view stride `this.pixelCount * 4` → `* 6`.
- After **`:260`** (`this.metaView[i * 4 + 3] = m.viewMask || 0;`) add the two
  new lanes, and change every `i * 4` to `i * 6`:
  ```js
  this.metaView[i * 6 + 4] = m.fixtureTypeId || 0;   // canonical FIX_* id
  this.metaView[i * 6 + 5] = m.pixelLocalIndex || 0;  // 0-based index within fixture
  ```

### 2. `marsin_engine/lib/marsin_wasm_runtime.js` — the parallel pack (keep in sync)

- **`:64`** `const metaBufSize = pixelCount * 4 * 4;` → `* 6 * 4`.
- **`:141`/`:147–150`** same 4→6 stride change + the two new lanes
  (`metaView[i*6+4] = m.fixtureTypeId`, `metaView[i*6+5] = m.pixelLocalIndex`).
- Both wrappers MUST change together (they pack the same `.wasm`); assert the
  buffer length matches the WASM's expected stride at init (mismatch must throw).

### 3. `marsin_engine/engine.js` — the two metaArray builders (current lines)

- **Boot path `:1019–1024`** (the `model.pixels.map(px => ({ ... }))`) — add:
  ```js
  fixtureTypeId: fixtureTypeId(px.fixtureType),   // from lib/fixture_type_constants.js (already imported)
  pixelLocalIndex: <0-based index within this px's fixture>,
  ```
- **Hot-reload path `:1242–1247`** — the identical `map` — add the same two
  fields. `fixtureTypeId` is already imported in engine.js (Phase 2). The
  `pixelLocalIndex` source is the within-fixture ordinal; today it is NOT a
  carried field — derive it at load (group consecutive pixels by `fId`, or have
  the sim exporter emit `pixelLocalIndex` per pixel). This is the one missing
  datum; the type id is fully ready.

### 4. FIX_* id table the host must use (canonical, append-only)

From `marsin_engine/lib/fixture_type_constants.js` — `fixtureTypeId(string)`
returns these; the host sets each pixel's `fixtureTypeId` from it. **Never
renumber an existing id** (a test pins them):

| fixtureType string | id | FIX_* role |
|---|---:|---|
| `''` / null / `'RawLed'` | 1 | `FIX_RAW_LED` |
| `'UkingPar'` | 2 | `FIX_PAR` |
| `'VintageLed'` | 3 | `FIX_VINTAGE_6` |
| `'ShehdsBar'` | 4 | `FIX_BAR_18` |
| `'ChauvetHaze4D'` | 5 | `FIX_HAZE` |
| `'TEFogMachine'` | 6 | `FIX_FOG` |
| (unknown) | 0 | UNTYPED (explicit "no known type", not a fallback target) |

At Tier B, `injectFixtureConstants` should switch from injecting the Tier-A
viewMask **bit** to injecting the canonical **id** (so `fixtureType == FIX_PAR`
becomes an integer equality against the new builtin). The authoring surface
(`FIX_PAR` etc.) is identical between tiers — `27_swipe.js` and any pattern
written against Tier A keeps working unchanged. The viewMask-bit merge in
`engine.js loadModel` (Tier A) is then removed and those high bits freed.

### Tier-A status of titanic (better than report-1 feared)

Titanic burns viewMask bits 0..25; the 4 present fixture types fit in free bits
26..29 (bit 30 spare), so **Tier-A FIX_* targeting works on titanic today** —
`27_swipe.js` renders on titanic right now. Tier B is the clean end-state
(integer equality, no viewMask bit pressure, frees the high bits), not a
prerequisite for titanic fixture-typing.
