### What each file does

- **`utils/channelExtrasApi.ts`** — added two typed fail-loud clients,
  cloned from `setChannelFaderMax`:
  - `setChannelHue(channelId, hue, { deck })` → `PATCH /mixer/channels/:id`
    (or `/deck/channel` when `{ deck: true }`) with `{ hue }`.
  - `setGlobalHue(degrees, autoRotateDegPerSec?)` → `POST /global-effect-hue`
    with `{ degrees, autoRotateDegPerSec? }` (omits the optional key when not
    passed). Both honour `res.ok` — a non-2xx returns `{ ok:false, error }`
    with the engine error body verbatim; never a fabricated success.

- **`components/GlobalEffectMacros.tsx`** — a new `HUE SHIFT` section rendered
  below the slot grid (deck variant only; omitted on the constrained
  `mixer-strip` row which has no vertical room). Two `HorizontalFader`s:
  - **HUE** 0-360° (mapped onto the fader's 0..1 contract), optimistic local
    set + throttled POST (the fader self-throttles `onChange` to ~50 ms during
    a drag, so each POST is naturally rate-limited).
  - **SPIN** -180..180 °/s, 0 = off (centred thumb; reads "OFF" at 0).
  - Reflects the engine `globalHueShift` `/ws/control` broadcast into local
    state, and seeds from `GET /globals` on boot. While auto-rotating, the UI
    shows the engine's reported degrees (the thumb animates with the spin); a
    `hueDraggingRef` guard suppresses the broadcast only while the operator is
    actively dragging the degrees fader so we don't fight their finger.
  - A live `hsl()` swatch previews the current hue. ≥44pt touch rows; colours
    from the palette. Fail-loud `Alert` on a rejected POST.

- **`app/(tabs)/mixer.tsx`** — a per-channel **HUE** row in `ChannelStrip`,
  placed right after the CAP row, cloning the CAP `HorizontalFader` block
  (0-360° mapped onto 0..1, amber→magenta `hueFill`, a small `hsl()` swatch,
  same `locked` gate). Handler `handleHueChange` is `useCallback([])` reading
  `channelsRef.current` — identical memo contract to `handleFaderMaxChange`,
  so `ChannelStrip`'s `React.memo` is not broken. Optimistic local apply +
  `PATCH … { hue }` + reconcile from the mixer broadcast (`channel.hue` is
  serialized by the engine and flows through `setChannels`) + fail-loud revert
  + `Alert` on rejection. Rendered unconditionally (gated only on the
  `onHueChange` prop being present), so the strip never shifts when hue=0.

## Known gaps / follow-ups

- **No live full-stack capture** here (no headless screenshot) — the instigator
  will bring up sim + engine + CaptainPad and verify both controls rotate the
  rendered RGB while W/A/UV stay put.
- **Global hue section is deck-variant only.** The `mixer-strip` variant
  (single horizontal row pinned to the mixer surface) is vertically
  constrained, so the two-fader HUE SHIFT section is intentionally not rendered
  there; the per-channel HUE row on each strip covers the mixer surface.

  a half-turn/sec, a comfortable operator range; widen the constant
  (`HUE_ROTATE_MAX_DPS`) if the operator wants faster spins.

  the other extras clients, but the mixer screen only wires the mixer-channel
  path (the deck strip lives in `index.tsx`, owned by another slice). A future
  deck-side HUE row can reuse `setChannelHue(id, hue, { deck:true })`.
