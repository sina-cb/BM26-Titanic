## What this delivers

The mapping now happens in the sim, which is the source of truth:

```
scenes/<scene>/views.yaml  ←  Views panel (create/rename views,
  + patches.yaml viewMask      assign selected fixtures, group chips)
        │ exportConfig() saves both (split server-side)
        ▼
saveModelJS() exports <scene>.js + <scene>.effects.js +
<scene>.viewmasks.js IN ONE PASS from the same pixel map
        ▼
engine loads + strictly validates (PR #11 machinery, unchanged)
```

### Scene-owned view registry (`src/dmx/view_registry.js`)
- `views.yaml` per scene: `groupBits` (auto-managed, stable across
  saves — new groups get the lowest free bit, removed groups free
  theirs, renames carry their bit via the group-rename hook) and
  `custom` views (`{name, bit, groups[]}`).
- Custom-view fixture membership lives in the fixtures' existing
  `viewMask` bitfield (patches.yaml) — stable across fixture renames;
  the old per-fixture raw int editor still works as a power-user view.
- **Groups derive from the EXPORTED PIXELS**, not fixture configs:
  effects-only fixtures (foggers/horns) never consume bits; LED
  strands and icebergs (which DO become pixels) get bits. First smoke
  run caught this exact class of bug (`Fogger` leaked in, titanic's 20
  strand/berg groups dropped) — fixed by deriving from
  `generatePixelMap()` output, the same universe the engine validates.

### Views panel (`src/gui/view_masks_editor.js`)
- Floating panel (👁 Views button under Save Configuration): lists the
  auto group views + bits; custom views with editable name/bit
  (validated: power of two, collision-free; bit edits migrate
  per-fixture masks), group chips, assign/unassign selected fixtures,
  member counts, delete (clears bit from all fixtures).

### Sidecar export
- Emitted with model+effects in `saveModelJS`: group-based views →
  `{name, bit, groups}`; fixture-based → `{name, bit, pixelIndices}`
  computed fresh per export (cannot go stale). Empty views are skipped
  with a warning. Guarded against mid-rebuild exports (empty pixel map
  must not wipe membership).
- Seeded `views.yaml` for all four scenes preserving every bit pinned
  in PR #11. Dome/test_bench multi-bit computed composites became
  single-bit explicit views (Apex 0x10, AllButApex 0x20, ParsAndBars
  0x08) — nothing referenced the old computed unions numerically.
  Logsville keeps 0x40/0x80 (patterns 70–117). **Titanic seed →
  regeneration round-trip is identity** (30 groups, same bits).

### Save/load hardening (the on-site stale-scene bug)
Root causes found (no single smoking gun — a class of holes):
1. **Auto-save defaults OFF with zero feedback** → edits silently lost
   on refresh, perceived as "loaded a stale version".
2. **2 s save debounce** → refresh inside the window lost the change.
3. **`exportConfig` silently dropped** saves during fixture rebuilds.
4. Save server wrote files non-atomically (truncation risk on crash).

Fixes (all in `gui_builder.js` / `save-server.js`):
- Dirty tracking on every mutation → persistent `● UNSAVED CHANGES`
  chip; cleared only by a confirmed 200 from the save server; failed
  saves show a red toast and stay dirty.
- `beforeunload`: prompts when dirty AND flushes the freshest config
  via `navigator.sendBeacon` (survives unload).
- Rebuild-time saves re-arm instead of dropping.
- All save-server writes atomic (temp + rename), including models.
- Latent `params` vs `configTree` array-reference divergence after
  first save inspected: by design (save snapshot), no consumer reads
  the stale side; left as-is.

## Continuation 2: isolation actually hides everything + real-UI proof

Picked up after the Antigravity agent's isolation work. Root causes
found and fixed for "lights and bodies still visible":

1. **Instanced glow dots are opaque `MeshBasicMaterial`** — blackening
   a non-member instance leaves a solid black sphere, and in the
   default `pixel_mapping` profile those dots ARE the fixture bodies.
   Fix (`animate.js`): while isolation is active, non-member instance
   matrices are zero-scaled every frame (membership can change live via
   Assign/Unassign), with exactly one restore pass on exit.
2. **Fog exclusion checked `config.type` only** — configs may carry
   `fixtureType` instead, so foggers were swept into isolation. Added
   shared `isEffectsOnlyFixture()` to `view_registry.js` (mirrors the
   exporter's routing predicate) and used it in both
   `applyViewMaskIsolation` and `light_pool._collectLightRequests`.
3. **Window pointer handler ate panel clicks** (the "UI is not doing
   much" report): every Views-panel click fell through to the
   raycaster, clearing the selection AND re-rendering the panel —
   destroying the clicked button before its click event fired. Fixed in
   `interaction.js` (panel/modal/HUD ids excluded); merged with the
   Antigravity agent's independent fix of the same bug during rebase.

Verification (all driven through the REAL UI, no API shortcuts):
- Isolation on test_bench default profile: exactly the member pixels
  remain visible (40/52), 12 non-members zero-scaled, fog machines
  stay, HUD exit restores everything (matrices + bodies). Assertions +
  screenshots in `.agent_renders/iso2_*.png`.
- Full operator workflow, 13/13: 👁 button → + New View via custom
  modal → group chips on new AND pre-existing views → real canvas
  click selects a fixture → selection survives panel clicks → Assign
  sets the bit → save lands in views.yaml → delete + save cleans disk.
- `npm run check` 2/2, `node --check` on all touched files,
  `git diff --check` clean. Test residue (URL renderer override
  persisted into common.yaml by saves) restored to webgpu by hand.
