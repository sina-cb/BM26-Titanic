## Scope

Engine side of TWO operator-requested features from the approved plan
(`.agent/02_reports/202606/20260620_27_hue_shifter_plan.md`, docs/39 §F-hue):
a **GLOBAL hue shifter** (first-class continuous knob + optional auto-rotate,
NOT a GEM slot) applied post-composite on `model.pixels`, and a **PER-CHANNEL
hue** applied pre-blend on each channel's interleaved RGBWAU buffer. Both rotate
**RGB only** via a luminance-preserving YIQ rotation (cos/sin precomputed once
per frame, ~9 mults/pixel), **leave W/A/UV byte-for-byte untouched** (mission-
critical exterior whites), are **gated on a non-zero angle (zero cost at the
default)**, and are allocation-free in the hot path. They **stack additively**.
No CaptainPad files touched — UI is a separate later wave.

## EXACT new API surface (for the follow-on UI wave)

**Global hue (model it like the blackout knob, not a GEM slot):**

- `POST /global-effect-hue`
  - Body: `{ degrees: number, autoRotateDegPerSec?: number }`
    - `degrees` — required; finite (or finite-parseable string). Non-finite ->
      **400**. Normalized server-side into `[0,360)` (e.g. 370 -> 10).
    - `autoRotateDegPerSec` — optional (default 0); finite, clamped `[-360,360]`.
      Non-finite -> **400**. Continuous spin in deg/sec (frame-rate independent).
  - 200 response: `{ status:'ok', hueShift:{ degrees, autoRotateDegPerSec } }`.
  - Side effects: persists `globalsState.hueShift`; broadcasts
    `{ type:'globalHueShift', hueShift }` on `/ws/control`; rebroadcasts mixer state.
- `GET /globals` includes `hueShift: { degrees, autoRotateDegPerSec }`.
- `globalEffectsController.getStatus().hueShift` mirrors live state (auto-rotate
  advances `degrees`, so a poller sees spin progress).
- **WS:** subscribe `/ws/control` for `{ type:'globalHueShift', hueShift }`.

**Per-channel hue:**

- `PATCH /mixer/channels/:id` and `PATCH /deck/channel` accept `{ hue: number }`
  - Validated by `validateHue`: non-finite -> **400**; finite normalized `[0,360)`.
- Serialized as `hue` (number, degrees `[0,360)`, default 0) on:
  - `GET /mixer` -> `channels[].hue`
  - `GET /deck/channel` -> `channel.hue`
  - WS `{ type:'mixer' }` channel objects + `{ type:'deck' }` channel object.
- Suggested UI: a HUE control on the channel strip (clone the CAP/faderMax row),
  PATCH the field; reflect the `hue` from mixer/deck WS state.
