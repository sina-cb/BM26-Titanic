## Scope
Ship a fully-working dark mode for CaptainPad with an operator-toggleable Config-tab setting. Light remains the default; the operator can flip to dark from the Config tab → APPEARANCE picker (LIGHT / DARK / SYSTEM), and the preference persists across iPad rebuilds and restarts via AsyncStorage (`@CaptainPad:themeMode`).

## Architecture

- New `CaptainPad/hooks/use-theme.tsx` — `ThemeProvider` context + `useTheme()` / `usePalette()` hooks. Resolves operator override (light/dark/system) against the OS `useColorScheme()`, persists to AsyncStorage.
- `CaptainPad/styles/globalStyles.ts` rewritten as a theme-aware hook factory (`useGlobalStyles()` + `makeGlobalStyles(palette)` + `GlobalStyles` type) so style atoms re-derive when the operator flips themes.
- `CaptainPad/constants/theme.ts` rewritten with a battle-tested dark palette (WCAG AA body text on the new dark `#0f1416` background) plus a typed `Palette` interface and new tokens: `onPrimary`, `errorContainer`, `errorContainerBorder`, `sidebarBackground`, `sidebarActiveBackground`, `sidebarActiveBorder`.
- `app/_layout.tsx` mounts `<ThemeProvider>` above the existing navigation `ThemeProvider`. The nav chrome now follows the operator's override (not just the iOS system) — light/dark navigators are picked from `useTheme().scheme`.
- `app/(tabs)/_layout.tsx` (sidebar + scene background) rewired to `usePalette()` so the always-mounted shell flips with the theme.
- New Config tab card `<AppearancePicker />` (LIGHT / DARK / SYSTEM three-way) following the existing pill/active-state convention.

## Migration approach (the bulk)

A Python helper (`~/tmp/dark_mode_helper/convert.py`) handled the mechanical conversion of ~20 files that aliased `const C = Colors.light` at module scope to a per-component `const C = usePalette()` call. The script also rewrote module-level `const styles = StyleSheet.create({...})` declarations that captured `C.*` into `function makeStyles(C: Palette[, globalStyles: GlobalStyles])` factories, and injected `const styles = useMemo(() => makeStyles(C[, globalStyles]), [C[, globalStyles]])` at the top of every consumer component. Module-level lookup tables that captured `C.*` (`STATE_STYLES` in OscStatusPill, `MIC_SIGNALS/STEMS_SIGNALS` in audio.tsx, the CARD/SUB_CARD/INPUT_STYLE objects in audio.tsx / osc.tsx, modalStyles in PlaylistPanel) were hand-converted to factory functions + per-component `useMemo`. Audio meter accents now reference token names (`'auto'` / `'primary'` / `'error'`) resolved at render via a `resolveAccent(slot.accent, palette)` helper so the dark mode meter colours follow the active palette rather than the boot-time one.

The Modulation MOD_GREEN (`#00a86b`) ghost-fill is left as a literal — it's a brand-anchored "auto-driven / live signal" green that reads cleanly on both backgrounds. Status pills with intentionally fixed semantic colours (OSC idle/unmapped amber + orange, the engine-lockout red overlay, the offline alarm banner) are also left as hard-coded literals with one-line `//` reasons since they should look the same regardless of theme — they're status signals, not chrome.

## Dark-palette contrast tuning

The starting dark palette from `theme.ts` was a placeholder ("Stage mode (Optional placeholder for later dark mode)"). I retuned the values for legibility on the iPad:

| Token | Before (placeholder) | After (tuned) | Why |
| --- | --- | --- | --- |
| `text` | `#ECEDEE` | `#e3e6e8` | softer at full white; reduces eye strain at 11pm |
| `background` | `#151718` | `#0f1416` | deeper neutral; raises card contrast |
| `surface` | `#151718` | `#0f1416` | mirrors background |
| `surfaceContainerLow` | `#1E1E1E` | `#171d20` | warmer tint, plays well with primary cyan |
| `surfaceContainerLowest` | `#2C2C2C` | `#0a0e10` | inverted from light (lowest = darkest, like cards over surface) |
| `surfaceContainerHigh` | `#111111` | `#1f262a` | lifted; was previously darker than `low` which inverted depth |
| `primary` | `#00daf3` | `#5ae0ee` | brighter cyan reads on dark; old value was the light `primaryFixedDim` |
| `primaryContainer` | `#006875` | `#003640` | proper "container" tier per Material naming |
| `onPrimary` (new) | n/a | `#003640` | dark text on bright primary stays readable |
| `secondary` | `#c6e4f4` | `#a8c5d4` | softer; pure cyan-tinged blue was hospital-cold |
| `error` | `#ffdad6` | `#ff8a82` | the old peach didn't read as alarm; the new red does |
| `ghostBorder` | `rgba(255,255,255,0.1)` | `rgba(180,195,200,0.18)` | slightly more visible at the same opacity |

Plus six new tokens: `onPrimary`, `errorContainer`, `errorContainerBorder`, `sidebarBackground`, `sidebarActiveBackground`, `sidebarActiveBorder`.
