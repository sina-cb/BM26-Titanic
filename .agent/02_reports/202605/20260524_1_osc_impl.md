## 1. What shipped

### Engine
- `marsin_engine/lib/param_center.js`
  - New registry fields: `live`, `broadcastHz`, `persist`, `portWatch` (auto-applied via `REGISTRY_DEFAULTS` / `withDefaults`).
  - `setHsvField()`, `setMany()` (atomic batch), `onChange(changedKeys)` hook, `hasPersistentDirty()`, `_setNoFire()` / `_setHsvFieldNoFire()` internals.
  - Audio params registered (post-Phase-6 split): `audioReactivity` (`/marsin/param/audioReactivity`, operator-tuned gain, `persist:true, live:false, portWatch:true`) and `stemsVocals` (`/marsin/stems/vocals`, OSC-driven live signal, `persist:false, live:true, broadcastHz:15, portWatch:false`). Earlier drafts called the gain `audioLevel`; it was renamed when CaptainPad gained dedicated UI so the operator knob and the live OSC stream don't share a name.
  - `getSchema()` exposes the new fields so downstream surfaces (CaptainPad, PortWatch) can filter by them.

- `marsin_engine/lib/api_server.js`
  - Single fan-out path via `paramCenter.onChange`: persistence + per-key throttled `sharedParams` broadcast.
  - Duplicate `applySnapshot` / `save` / `broadcastWs` removed from `POST /param-center` and WS `setSharedParam`.
  - `lastOscStats` cached and **replayed on every WS connect** so new CaptainPad clients see correct pill state inside one frame.

- `marsin_engine/lib/osc_listener.js` (new)
  - UDP via `osc-min`, canonical bindings auto-built from CPC schema + custom + object-form bindings from `config.yaml`.
  - IPv4/IPv6 allowlist normalisation (`127.0.0.1` ≡ `::1` ≡ `::ffff:127.0.0.1`).
  - Atomic-batch dispatch through `paramCenter.setMany()` so one packet = one broadcast.
  - Split counters (`rx`, `mapped`, `dropped`, `invalid`), rate-limited per-minute warnings.
  - Hard startup errors for config mistakes (out-of-range port, unknown CPC key, bad arg index, canonical collision, bad allowedSender IP) — engine boots, OSC is disabled, error logged.

- `marsin_engine/engine.js`
  - `OscListener` instantiated and started **last** (after `loop.start()`); stopped **first** in shutdown.
  - Failure mode: instantiation errors caught → OSC disabled, engine continues.
  - Initial `oscStats` snapshot published at boot for the disabled / waiting state.

- `marsin_engine/config.yaml`
  - New top-level `osc:` block. Default `enabled: false`. Port preset to `10000` for the operator's rig.

### CaptainPad (Phase 6)
- `CaptainPad/hooks/useEngineState.ts`
  - Handles `oscStats` WS messages → `EngineLiveState.oscStats`.
  - New `useOscStatus()` selector that derives one of four pill states (`off | idle | unmapped | live`) per `docs/24 §10.2`. Includes `STALE_MS = 2_000` debounce so a single dropped stats tick doesn't flicker the pill.

- `CaptainPad/components/OscStatusPill.tsx` (new)
  - Compact pill in the GLOBALS strip; tap opens a diagnostic sheet with listener address, bindings count, allowedSenders, per-second counters (rx / mapped / dropped / invalid), and last sender / last packet age.
  - Visual states colour-mapped: muted (off) / amber (idle) / red (unmapped) / cyan (live).

- `CaptainPad/components/CPCControls.tsx`
  - Pill inlined into the GLOBALS header label. No layout shift — the placeholder during the first frame matches the rendered-state pill size.
  - Added a second row for audio: `audioReactivity` `MiniFader` (operator-tuned gain) + `StemsMeter` read-only meter (raw OSC level layered with effective-after-gain). Matches the rest of the strip's theme.
  - Color picker rebuilt as **hue-only**: S and V are pinned to 100% on write to avoid washed-out stage colours. Modal includes a 40 px preview chip + an explanatory hint. Swatches in the header are drawn at full S/V to advertise the policy.

- `CaptainPad/components/DeckTopBar.tsx` (new)
  - Deck top bar mirroring the Marsin Mixer header: brand title, connection status badge, and master fader. **No add-channel buttons** — channel management stays on the mixer tab. Master is read from `useEngineState().master` (extended to track the mixer broadcast's `master` field) so the deck stays in sync with mixer/PortWatch/API writes. PATCH writes throttled to ~30 Hz.

- `CaptainPad/app/(tabs)/index.tsx`
  - Top bar inserted above `CPCControls` on the deck so the layout matches the mixer tab visually.

### Reference sender + live probe
- `marsin_engine/tests/osc_audio_sender.py` — `--value` / `--mic` / `--sweep` modes, defaults to `127.0.0.1:10000 /marsin/stems/vocals`.
- `marsin_engine/tests/osc_live_listener.mjs` — standalone OSC probe that prints every CPC write + per-second stats. Used for the cross-machine validation below.

### Live cross-machine validation
Operator's analyser at `10.1.1.172` sending `/marsin/stems/vocals` → port 10000:

```text
📡 OSC listener on 0.0.0.0:10000 (13 binding(s), 0 allowedSender(s))
$ curl /param-center | jq '.params.stemsVocals'
{ "value": 0.4642, "lastSource": "osc", "lastOrigin": "osc:10.1.1.172:62625", "lastRevision": 105 }
$ # +2 s
{ "value": 0.3964, "lastSource": "osc", "lastOrigin": "osc:10.1.1.172:62625", "lastRevision": 245 }
[stat] rx=60 mapped=60 dropped=60 invalid=0
```

- `lastRevision` advanced ~70 ticks/sec; no disk I/O for the live param.
- `dropped≈60` is the analyser's `/_samplerate` meta address (no binding, silently dropped per spec).
- Clean SIGINT: listener stops first, render loop stops, sACN blackout sent, exit. No port leak.

## 2. Handoff — pick this up here

### Wire the operator's rig
1. Set `osc.enabled: true` in `marsin_engine/config.yaml` (port already `10000`).
2. Boot: `node engine.js --pattern … --model …` — expect `📡 OSC listener on 0.0.0.0:10000`.
3. Open CaptainPad — the pill in the GLOBALS strip should flip from `OSC OFF` → `OSC WAITING` → `OSC 60 msg/s` (or similar) within a couple of seconds of the analyser sending.

### Deferred work (designed + safe to delay)

**Phase 7 — PortWatch bridge `compact_status` schema-filter.** The CPC already exposes `portWatch` per field; the bridge just needs to:
- Fetch `/param-center/schema` at boot and on every engine reconnect.
- When composing `compact_status`, drop any field where `schema[key].portWatch === false`.
- Optional: refetch on a new `schemaChanged` WS hint.
Until this lands there is no risk because no live param currently flows into the bridge's CPC mirror — `audioLevel` / `stemsVocals` are excluded from the bridge's source data path. If you add a *non-live* persistent param that should not go over LoRa, fix this first.

**Phase 5.2 — optional demo pattern (`test/audio_pulse.js`).** Trivial: `export var stemsVocals; export function render(i) { hsv(0, 0, stemsVocals) }`. Skipped because the live cross-machine validation already proved the wire path.

**Phase 6+ polish — CaptainPad bindings editor.** Design lives in `docs/24 §15`. Would extend `OscStatusPill` diagnostic sheet with a per-binding list + add/remove flow backed by new `GET/PUT /osc/bindings` endpoints persisting to a new `osc_bindings.yaml`. Out of scope for v1.

### Files an operator / next agent should touch first
- `marsin_engine/config.yaml` — operator-facing config; set `enabled`, `port`, `allowedSenders`, custom `bindings`.
- `marsin_engine/lib/param_center.js:15-68` — the registry. Add new global params here following `.agent/01_skills/04_add_new_global_param.md`.
- `CaptainPad/components/CPCControls.tsx` — add sliders / pills for new operator-facing params.
- `docs/24_osc_integration.md` — the spec; keep it in sync if behaviour shifts.

### Known-clean operational properties
- Engine boots fine with OSC disabled (default).
- Engine boots fine with OSC enabled but a misconfigured `osc.bindings` block — listener disables itself, error logged, render loop runs.
- Engine boots fine with OSC enabled and port already bound — listener disables itself, error logged.
- Live params do **not** persist (no `param_center_state.yaml` churn). A 5-minute soak at 60 Hz leaves mtime unchanged.
- CaptainPad reflects OSC writes within one WS round-trip (sub-second on Wi-Fi).
- The pill replays correctly on CaptainPad cold-mount because of `lastOscStats` cache + replay.

### Out-of-scope (explicit non-goals — do not absorb into v1)
Per `docs/24 §15`: per-pattern local export OSC control, MIDI source, OSC outbound feedback, CaptainPad bindings editor, per-named-sender source-lock leases, TCP/WS OSC transport. File a follow-up report if any becomes urgent.
